# Harness — how to run everything

Everything heavy runs on the Mac Studio (`ssh studio`, key auth). The tools in
`tools/` detect where they are: if the Unity 6000.3.20f1 binary exists locally
they run locally, otherwise they `ssh studio`, run the same script in the Studio
clone, and (for capture) rsync `shots/` back. Every script resolves the repo root
from its own location, so it works from any clone or worktree
(`~/dev/lanes/<lane>` on the Studio). Override the remote with `AOT_STUDIO`
(ssh alias) and `AOT_STUDIO_REPO` (path relative to `$HOME`, default
`dev/aot-fable-5.1`); force the ssh path with `AOT_FORCE_REMOTE=1`.

| Command | What | Measured on the Studio |
|---|---|---|
| `tools/setup.sh` | one-time: URP assets, base materials, Main scene, player settings (`Setup.All.Run`) | 13 s (+39 s first import) |
| `tools/capture.sh <piece> [a,b]` | render `tools/poses.json` poses to `shots/<piece>/<pose>.png`, 1920x1080 | 12 s for 4 shots |
| `tools/test.sh [editmode\|playmode]` | EditMode + PlayMode tests, XML in `test-results/` | 19 s (8 s + 11 s) |
| `tools/build.sh mac` | arm64 standalone → `builds/mac/AOT.app` | MAC_TIME |
| `tools/build.sh webgl` | → `builds/webgl/` (gzip + decompression fallback, GitHub Pages safe) | WEBGL_TIME |
| `tools/play.sh [seed]` | launch the mac build on the Studio, windowed 1080p, `-seed n` | instant |
| `node tools/progress.mjs` | regenerate `progress.html` from `gauntlet/` | 0.03 s |
| `tools/unity.sh <log> args…` | raw Unity batch wrapper; log in `logs/<log>.log` | – |

Every script prints one verdict line: `CAPTURE_OK n shots` / `CAPTURE_FAIL reason`,
`BUILD_OK target Ns MB` / `BUILD_FAIL`, `TEST_OK` / `TEST_FAIL`, `SETUP_OK`, and exits
non-zero on failure. Full Unity logs are in `logs/` (ignored).

## Runtime contract

- `Shared.Ctx.Set(name, obj)` / `Ctx.Get<T>(name)` (default when missing) /
  `Ctx.Require<T>(name)` (throws). Bootstrap registers: `seed` (int),
  `bootstrap`, `camera` (Camera), `orbit` (OrbitCamera), `light` (Light),
  `ground`, `mikasa`, `titan`, `placeholder` (GameObject), `townCenter` (Vector3).
- `Shared.Bootstrap` runs from `RuntimeInitializeOnLoadMethod(AfterSceneLoad)`;
  `Bootstrap.Ensure()` is idempotent. `-seed n` on the command line seeds
  `UnityEngine.Random` (default 42). Fixed timestep 1/60.
- The stub street (`placeholder`) is 16 boxes along +Z from z=-40 to z=40, the
  Titan capsule stands at (0, 7.5, 60), Mikasa at (0, 1, -20). Town replaces the
  placeholder (`Destroy(Ctx.Get<GameObject>("placeholder"))`).
- `Shared.Mats.Lit(color)` / `Unlit` / `Sky` clone the Resources base materials.
  Do not `Shader.Find` at runtime for a shader no asset references: it is
  stripped from builds.
- Command-line helpers: `Bootstrap.Arg("-flag")`, `Bootstrap.ArgInt("-flag", d)`.

## Capture rig

`tools/capture.sh <piece> [pose,pose]` →
`Unity -batchmode -executeMethod Capture.Entry.Run -piece X -poses a,b -shots <repo>/shots`
(no `-quit`, no `-nographics`). `Entry.Run` opens `Main.unity` and enters play mode;
`CaptureRunner` picks the same args up at runtime, sets `Time.captureFramerate = 60`,
waits 10 warm-up frames, then per pose (sorted by `timeSec`): advances frames until
`Time.time` reaches `timeSec` (never rewinds), places the camera, waits 3 frames,
renders with `Camera.Render()` into a 1920x1080 MSAA RenderTexture, `ReadPixels`,
writes the PNG. Then `EditorApplication.Exit(0)`. Add poses to `tools/poses.json`;
`-posesFile` overrides the file. The orbit camera is disabled during capture.

## Gotchas (all hit for real)

- `WaitForEndOfFrame` never fires in `-batchmode` (no game view). The capture hung
  forever on it. Use `yield return null` + `Camera.Render()` into a RenderTexture.
- The first ~3 frames of play mode render before the skybox and runtime textures
  are uploaded: an everything-white-and-orange shot. Hence the 10-frame warm-up.
- A pose that is pitched too steeply sees no sky and reads as broken lighting. Keep
  the horizon in frame unless you mean it (first `overview` had this).
- macOS has no `timeout`; `tools/unity.sh` polls the PID and kills after
  `UNITY_MAX_SEC` (default 3600). A hung capture is a hung Unity: `pkill -9 -f
  Unity.app/Contents/MacOS/Unity` on the Studio.
- Only one Unity instance per project directory at a time (Library lock). Capture,
  test and build are sequential. Parallel lanes need separate worktrees, each with
  its own `Library/` (first import ~40 s).
- `ProjectSettings.activeInputHandler` has no public API; ProjectSetup sets it to
  2 (Both) through `SerializedObject`.
- Batch stdout is empty; Unity writes only to `-logFile`. The scripts grep the
  verdict line out of `logs/<name>.log`.
- Log noise you can ignore: `ArgumentOutOfRangeException … SearchDatabase` at editor
  startup (QuickSearch indexing in batch mode), `[usbmuxd]`.
- `git pull --ff-only` on the Studio fails silently inside the ssh wrappers if the
  branch diverged; the scripts still run whatever is checked out. Check
  `git -C ~/dev/aot-fable-5.1 status` when results look stale.
- Meta files: never write them by hand. Let Unity generate them on the Studio and
  commit from there (the Studio has push access).

## Progress page

`gauntlet/<piece>/round-N.json`:
`{piece, round, verdict:"win"|"lose", gap, score:0-10, shots:[paths], reference:[paths], ts}`.
`gauntlet/status.json`: `{wave, pieces:{name:{state, round, score}}}`.
`node tools/progress.mjs` writes `progress.html` (dark, one card per piece, latest
shot = `shots/<piece>/latest.png`, score sparkline, gap text, wave + timestamps).
